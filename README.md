# Flowrium

본인의 ChatGPT 계정으로 여러 프로젝트와 역할별 AI 대화를 운영하는 Mac과 Windows 앱입니다. 조사, 문서, 주간업무보고, 업무 마감, 팀 업무를 독립된 대화에 맡기고, AI가 실제 프로젝트 자료와 작업 기록을 읽어 결과를 작성하고 저장합니다. 대화 사이의 요청과 결과 전달, 결정 검토, 목표와 기억, 산출물까지 한곳에서 이어갑니다.

[다운로드](https://hyeondk.github.io/flowrium/), [릴리스와 설치 파일](https://github.com/hyeondk/flowrium/releases), [터미널 설치](docs/TERMINAL-INSTALL.md), [기능별 지원 범위](docs/FEATURES.md), [Codex 대화 연결](docs/CODEX-CHAT-LINK.md), [사용 범위와 전환 상태](docs/REPLACEMENT-STATUS.md)

Google 일정 작업 화면과 오늘 일정·메일 요약, 공식 Dots 웹 탭을 추가했습니다. 현재 검증과 배포 준비 상태는 [기능별 남은 항목](docs/REMAINING-261115_02.md)에서 구분합니다. 공개 설치본은 [릴리스](https://github.com/hyeondk/flowrium/releases)에서 확인하세요.

## 자료 관리와 실행 도구

- [Codex 프로젝트 대화 연결](docs/CODEX-CHAT-LINK.md): 기본값인 **같은 대화로 연결**은 원래 대화 식별자를 유지합니다. 본문, 도구 기록, 첨부를 읽어 표시하고 원문을 로컬에 보관합니다. 사라진 임시 이미지는 기록에서 정확히 일치하는 사본을 복구하며, 원본이 없는 경우를 구분합니다. 수동 새로고침에 더해 20초마다, 창에 돌아올 때도 갱신을 시도하며, 한 대화는 한 앱에서 작업합니다. 별개로 작업하려면 **독립 사본 만들기**를 선택합니다.
- 설정은 분류별 탐색과 본문 스크롤을 분리했습니다. 카드 내부는 기본 20px 여백(좁은 화면 16px)을 두고, 주요 실행 버튼과 투명한 보조 행동을 구분합니다. 중앙 팝업과 왼쪽 정렬 메뉴를 유지하며 320px 폭에서도 가로 넘침을 검사했습니다.
- [전체 자료 이관](docs/MIGRATION.md): 원본 미리보기, 대상 폴더 지정, 프로젝트와 일반, 통합 대화, 첨부와 도구 기록, 기억, 설정, 초안, 원문 보관, 적용 전 백업, 실패 복구를 제공합니다. 인증과 비밀값은 옮기지 않습니다. 적용 후 재시작하며 이전 엔진의 실행 문맥은 새 요청으로 연결합니다.
- [로컬 음성 서버](docs/LOCAL-VOICE.md): 준비한 실행 파일과 인자를 검토해 시작, 중지, 재시작하고 상태와 로그를 확인합니다. 앱이 관리하는 프로세스만 종료하고, 이미 실행 중인 외부 서버는 보존합니다. 음성 모델과 서버 설치는 별도로 필요합니다.
- [자동 포트표](docs/PROJECT-PORTS.md): 프로젝트 번호와 웹, 관리자, API, 데이터베이스, 보조 포트를 배정하고 실제 수신 충돌, 예약, 사용자 지정, 주소와 환경변수 복사를 제공합니다. 검사 시점의 사용 여부를 표시하며 서버 실행이나 다른 프로세스 종료를 수행하지 않습니다.
- 주간업무보고와 업무 마감은 중앙 팝업에서 프로젝트, 기간, 추가 요청, 계정 모델과 생각의 깊이를 선택해 AI에게 맡깁니다. 연결에서 제공하지 않는 모델 명칭을 임의로 표시하지 않습니다. [공식 연결 모델 목록 안내](https://learn.chatgpt.com/docs/app-server)

## 업무 흐름

- **왼쪽 메뉴**는 아이콘 위에 마우스를 올리면 펼쳐지고 벗어나면 접힙니다. 본문 위치를 밀지 않으며, 고정 버튼이나 키보드로도 조작할 수 있습니다.
- **오른쪽 대화함**에서 통합 채팅, 프로젝트 대화, 일반 대화를 구분합니다. 대화를 열어도 왼쪽 화면을 유지하며, 명시적으로 패널 폭과 고정·겹쳐 보기·입력창만 보기를 선택합니다. 일반 대화는 프로젝트 없이 시작하고, 통합 채팅은 제공된 프로젝트 현황을 읽습니다. 통합 채팅의 구현 요청은 결정함에서 승인한 뒤 해당 프로젝트 대화에서 실행하고 결과를 회신합니다.
- **작업중**, **대기**, **결정**을 메뉴와 대화함, 하단 현황에서 구별합니다. 작업중은 실제 실행을 뜻하고, 결정은 허락이나 답변 요청을 뜻합니다. 대기는 다음 진행을 기다리는 대화입니다. 완료한 모든 대화를 대기 수로 세지는 않습니다.
- **화면**은 나눔스퀘어라운드와 일정한 행 높이, 아주 연한 파란 배경과 청회색과 남색 강조를 사용합니다. 중앙 팝업, 알림, 하단 시트, 스위치, 체크박스, 좋아요 반응, 잠금 해제, 로딩, 제목 순차 등장과 동작 줄이기를 지원합니다. [화면 움직임 기준](docs/UI-MOTION.md), [보고 팝업 예시](docs/weekly-popup.png)
- **대시보드**에서 오늘의 목표, 기한, 시작과 완료, 결정 대기를 확인합니다. 실제 업무 기록의 7일 그래프와 프로젝트 분포, 최근 커밋 추이를 볼 수 있고 **AI로 오늘 할 일 정리**로 별도 계획 대화를 시작합니다.
- **채팅**에 이미지, 파일, 캡처를 첨부합니다. 작업 중 새 지시는 저장된 대기열로 보내고 취소하거나 이어서 실행합니다. 기준 요청에서 실제 내부 대화를 분기하거나 요청 직전으로 되감아 다시 작성할 수 있습니다.
- **주간업무보고, 업무 마감**은 프로젝트, 기간, 사유, 메모, 모델을 선택하면 AI가 완료 업무와 대화, Git과 변경 요청의 실제 근거로 보고와 인계를 작성합니다. 결과 대화와 산출물을 함께 보존합니다.
- **업무 연결, 비서**에서 대화 사이 요청과 결과 회신, 통합 결정함, 예약 알림과 보고를 운영합니다. 정기 감시와 팀 자동 운영은 직접 켠 경우에만 수행합니다. AI가 제안한 외부 일정 변경이나 저장소 실행은 결정함에서 검토한 뒤 승인합니다.
- **프로젝트**의 목표와 수치 진척, 이월, 반복 일정, 여러 저장소와 대화 작업 위치를 관리합니다. AI에게 목표 정리와 규칙, 회의록, 디자인 문서 작성을 맡길 수 있습니다. 보고서와 발표자료도 생성합니다.
- **산출물**의 HTML을 안전한 화면으로 미리 보고 수정, PDF, 편집 가능한 발표자료 재변환, 삭제와 복원을 수행합니다. 저장 공간도 미리 본 계획에 따라 압축 보관하고 복원합니다.
- **휴대폰**에서 첨부, 실행 지시, 팀과 결정, 비서, 모델 설정을 다룹니다. 알림은 기기와 종류를 직접 선택합니다. 카카오 나와의 채팅과 허용한 메일 주소로 일회용 연결 주소를 전달할 수 있습니다.
- **음성, 음악**은 선택한 로컬 음성 서버와 연속 듣기, 호출어, 답변 읽기를 지원하고, 재생 중인 곡의 가사를 찾아 시간에 맞춰 표시합니다. [로컬 음성 준비](docs/LOCAL-VOICE.md)

## 시작하기

1. 다운로드 페이지에서 **Apple Silicon Mac** 또는 **Windows 64비트**용 설치 파일을 선택합니다. 다운로드 버튼은 해당 플랫폼의 배포 파일이 준비되면 활성화됩니다. Mac에서는 DMG를 열어 앱을 응용 프로그램 폴더로 옮기고, Windows에서는 EXE 설치 프로그램을 실행합니다.
2. 대시보드에서 **프로젝트 추가**로 목표와 담당자, 저장 위치를 정하거나 **기존 폴더 연결**을 선택합니다. 여러 프로젝트가 서로 다른 드라이브나 위치에 있어도 각각 연결할 수 있습니다.
3. 설정에서 Codex 연결을 누릅니다. 로그인 안내가 표시되면 브라우저에서 **사용자 본인의 ChatGPT 계정**으로 로그인합니다. 설치 파일에는 플랫폼용 Codex가 들어 있습니다.
4. 오른쪽에서 통합, 일반 대화를 시작하거나 프로젝트에서 기능별 대화를 열고 목표를 적습니다. 계획과 검토는 파일을 읽는 작업이며, 구현에서는 프로젝트 파일을 변경할 수 있습니다. 별도의 실행 승인이 표시되면 내용을 확인하고 결정합니다.
5. 다른 작업으로 전환했다가 대화를 다시 열거나 필요한 대화를 마크다운으로 내보냅니다.

계정 인증은 공식 Codex가 관리합니다. 설치한 사람마다 자신의 계정, 프로젝트, 모델 목록을 사용합니다. 브라우저에서 이어가려면 상단의 **ChatGPT 열기** 버튼을 눌러 복사한 내용을 원하는 웹 대화에 직접 붙여 넣습니다.

대화 상단의 **대화 관리**에서 각 업무가 사용할 모델과 추론 강도를 따로 정할 수 있습니다. 기존 ChatGPT 웹 대화를 이어 쓰려면 그 대화의 주소를 저장한 뒤 상단의 **ChatGPT 열기** 버튼을 누르세요. 현재 대화의 최근 메시지가 클립보드에 복사되고, 연결한 웹 대화가 열립니다. 웹 대화의 내용은 사용자가 직접 붙여넣습니다.

## 프로젝트에서 일하는 방법

- **프로젝트 추가**에서 목표, 담당자와 참여자, 시작일과 마감일을 정합니다. 원하는 위치에 새 폴더를 만들거나 기존 프로젝트 폴더를 사용할 수 있습니다. 선택하면 규칙, 디자인, 회의록 폴더를 만들거나 지정한 GitHub 저장소를 빈 폴더로 복제합니다.
- **프로젝트 홈**에서 주간, 월간 목표와 체크리스트, 다음 업무와 최근 커밋을 확인합니다. 상세 탭은 홈, 업무 현황, 팀, GitHub, 규칙, 디자인 시안, 회의록, 문서, 프로젝트 설정입니다. 규칙이나 회의록을 작성하면 해당 프로젝트의 실제 문서로 저장합니다. 보관한 프로젝트는 왼쪽 **완료**에서 재개합니다.
- **주간업무보고**에서는 보고할 프로젝트와 이번 주, 지난주, 직접 지정 기간, 메모와 사용할 모델을 고릅니다. 완료 업무, Git, 변경 요청, 대화 기록을 AI가 읽어 보고서를 작성하며 **작성된 보고**에서 다시 엽니다. **업무 마감**은 점심, 퇴근, 회의, 기타 사유와 메모를 바탕으로 최근 12시간 활동 프로젝트별 인계 대화를 만듭니다.
- **업무 현황**에서 새 업무를 만들고 종류와 담당 역할, 목표를 정합니다. 주간업무보고는 기간을, 문서 작성은 독자와 용도를 지정할 수 있습니다. 대화마다 역할 지시가 유지됩니다. 리서치는 실시간 웹, 저장된 검색 결과, 프로젝트 자료 중 조사 범위를 선택하고, 기간 보고에는 해당 프로젝트의 실제 완료 기록과 커밋을 사용합니다.
- 업무 대화에서 체크리스트를 추가하고, 상태를 **진행 중, 검토 중, 완료**로 바꿉니다. 완료 시점의 요약과 커밋 기록을 이후 보고에 활용할 수 있습니다.
- 필요한 답변에서 **답변을 산출물로 저장**을 선택하면 프로젝트의 `산출물/` 아래에 업무 유형과 대화별로 파일을 만듭니다. 마크다운, HTML, PDF, 발표자료(PPTX) 중 필요한 형식을 고를 수 있습니다. **산출물**에서 `산출물/`, `docs/`, `outputs/` 안의 문서를 검색할 수 있습니다. 지원하는 텍스트 문서는 앱에서 미리 보고, 다른 형식은 파일 위치에서 엽니다. 기존 문서는 파일 선택이나 끌어놓기로 추가할 수 있습니다.
- **프로젝트 팀**에서는 역할별 지시와 작업 방식을 정하고, 공동 요청을 여러 대화에서 동시에 실행합니다. 팀 실행 기록에서 역할별 상태를 확인하고 해당 대화로 돌아갈 수 있습니다.
- **대화 관리**에서 이름을 바꾸거나 기준 요청에서 분기할 수 있습니다. 요청 직전까지 되감으면 다음 요청은 남긴 기록을 바탕으로 시작합니다. 일반 업무 대화와 독립 사본은 문맥 압축을 요청할 수 있습니다. 원래 앱과 같은 대화로 연결한 경우에는 분기, 되감기, 압축을 제한하므로 필요하면 독립 사본을 만드세요.
- **형상관리**에서 선택 파일의 차이와 커밋, 현재 브랜치 푸시, GitHub 변경 요청 조회, 생성, 병합을 실행할 수 있습니다. 로컬 Git과 앱에 내장한 GitHub CLI를 사용하며 원격 작업에는 사용자가 권한을 가진 저장소와 GitHub 인증이 필요합니다. 프로젝트 폴더를 운영체제 터미널에서 열 수 있습니다.
- **저장소**에서 현재 브랜치, 변경 파일, 최근 커밋을 확인합니다. 깃 저장소가 없는 프로젝트도 대화와 산출물을 사용할 수 있습니다.

## 여러 업무 살펴보기

대시보드의 **승인함**에서 다른 대화가 기다리는 실행 요청도 확인해 허용하거나 거절할 수 있습니다. **작업 현황**에서 모든 프로젝트의 실행 중인 업무와 최근 요청을 보고, 해당 대화를 열거나 중단할 수 있습니다. 이 컴퓨터의 CPU와 메모리 상태도 표시합니다.

## 계정과 외부 자료 연결

- 설정에서 기기 잠금 번호를 등록하면 사이드바의 **잠금**으로 작업 화면을 가릴 수 있습니다. **로그아웃**은 연결한 ChatGPT 계정의 세션을 종료합니다.
- 설정의 **메일과 일정, 드라이브**에서 직접 준비한 Google 데스크톱용 OAuth 클라이언트를 입력하고 브라우저에서 본인 계정을 승인합니다. 일정, 메일과 파일을 조회하거나 지원되는 문서를 현재 프로젝트로 가져올 수 있습니다. Google Cloud에서 사용할 Gmail, Calendar, Drive API를 켜야 합니다. 연결 정보는 운영체제의 암호화 저장 기능을 사용합니다.

## 휴대폰에서 업무 이어가기

데스크톱 설정의 **휴대폰 연결**에서 연결을 켜고 표시된 주소를 본인 휴대폰의 브라우저로 여세요. 데스크톱에서 연결한 프로젝트, 팀 상태와 지원 문서를 확인하거나 대화를 만들어 요청을 보내고 실행을 중단할 수 있습니다. **승인함**에서 실행 요청을 승인하거나 거절합니다. Codex가 추가 질문을 보내면 보기를 고르거나 직접 답해 작업을 이어갑니다. 비밀 입력이 포함된 질문은 데스크톱에서만 확인하고 답할 수 있습니다. 데스크톱을 잠그면 모바일에서 작업 공간을 볼 수 없습니다. 연결 주소는 접근 권한을 포함하며 연결을 종료하면 해당 주소의 접근이 끝납니다.

## 기존 Codex 대화 이어가기

**설정 → 대화와 자료 → 프로젝트 대화 연결**에서 이 기기의 대화를 찾고 미리 본 뒤 연결합니다. 기본값인 **같은 대화로 연결**은 원래 `threadId`를 유지해 양쪽 앱에서 순서대로 이어 씁니다. 한 앱의 작업을 마친 뒤 다른 앱에서 **대화 새로고침**을 누르세요. Flowrium은 실행 중이 아닐 때 20초 간격과 창에 돌아올 때도 갱신을 시도합니다. 원래 앱에서 실행 중이던 대화는 작업을 마친 뒤 수동 새로고침으로 확인해야 합니다.

같은 대화에 두 앱이 동시에 쓸 수는 없습니다. 원래 앱이 대기 상태여도 작성 연결을 보유하면 해당 채팅을 떠나거나 앱을 종료한 뒤 재시도하세요. Flowrium은 연결 대화의 실행을 마치면 전용 실행 연결을 닫아 반환합니다. 원래 앱 전용 도구는 Flowrium에서 실행할 수 없으며, 연결 대화의 분기, 되감기, 압축이 필요하면 **독립 사본 만들기**를 선택하세요. [사용법과 제한](docs/CODEX-CHAT-LINK.md)

기존 **작업 기록 → Codex 기록 가져오기**는 프로젝트 경로에 맞는 사용자 메시지와 답변 본문을 한 번 복사하는 별도 기능입니다. 그 사본에는 이후 자동 갱신, 전체 도구 기록, 첨부 원본, 원래 실행 문맥 연결을 제공하지 않습니다. ChatGPT 웹 대화 목록의 자동 가져오기도 지원하지 않습니다.

## 프로젝트와 저장 위치

| 위치 | 내용 |
| --- | --- |
| 선택한 프로젝트의 `.flowrium/project.json` | 프로젝트 식별자 |
| 같은 폴더의 `.flowrium/sessions/` | 대화 본문과 개정 기록 |
| 같은 폴더의 `.flowrium/codex-source/` | 연결한 Codex 대화의 로컬 원문 보관 |
| 운영체제의 Flowrium 앱 데이터 `conversation-hub/` | 계정별 통합 채팅과 일반 대화, 첨부와 개정 기록 |
| 같은 폴더의 `산출물/` | 사용자가 저장한 답변 파일 |
| 운영체제의 Flowrium 앱 데이터 폴더 | 이 컴퓨터에서 연결한 프로젝트의 위치, 앱 설정, 실행 연결 식별자 |
| Codex가 관리하는 기기별 데이터 | 계정 인증과 Codex 자체 실행 기록 |

다른 컴퓨터에서 이어가려면 숨김 폴더인 `.flowrium/`을 포함해 프로젝트 전체를 옮긴 뒤 해당 프로젝트 폴더를 선택하세요. 새 기기에서는 자기 계정으로 연결합니다. 한 대화에 대해 서로 다른 변경이 발견되면 앱이 기존 개정을 보존하고 충돌을 알립니다. 한 기기에서 작업을 마친 후 다른 기기에서 여세요. 원래 Codex 대화와의 연결은 계정과 기기를 확인하므로 폴더 복사만으로 새 기기의 연결까지 복원되지는 않습니다.

공개하는 프로젝트에서 개인 대화를 제외하려면 그 프로젝트의 `.gitignore`에 `.flowrium/`을 추가하세요. 대화를 앱에서 삭제하면 개정 기록에 삭제 상태가 남습니다.

## 업데이트

공개 버전은 **YYMMDD_순번** 형식입니다. 날짜 버전부터는 날짜와 순번으로 새 공개 릴리스를 확인합니다. 새 버전 알림의 **업데이트 후 재시작**은 운영체제에 맞는 파일을 받고 확인값을 검사한 뒤 교체를 진행합니다. 설정의 **새 버전 확인**으로도 확인할 수 있습니다. [버전 규칙](docs/VERSIONING.md)

Windows에서는 확인한 설치 프로그램으로 교체하고 다시 시작합니다. Mac에서 앱 안의 교체는 **Developer ID 서명과 Apple 공증을 통과한 새 버전**에 적용됩니다. 새 버전이 미공증이면 기존 앱은 계속 실행되며 **수동 설치 파일 받기**로 다운로드 페이지를 열어 DMG를 직접 설치합니다.

버전별 설치 파일과 서명 상태, SHA-256 확인값은 [GitHub 릴리스](https://github.com/hyeondk/flowrium/releases)에 있습니다. **0.6.0 이하에서는 날짜 태그를 인식하지 못하므로 이번 한 번 새 설치본을 수동으로 설치해야 합니다.** [터미널 설치기](docs/TERMINAL-INSTALL.md)도 사용할 수 있습니다. 프로젝트 폴더의 대화 기록은 앱과 별도로 저장됩니다. 미공증 Mac의 수동 설치 조건은 날짜 버전에서도 동일합니다.

## 개발과 검증

설치본에는 프로젝트 서비스와 내장 터미널에서 사용할 Node.js 24.22.3 LTS, npm 11.19.1, GitHub CLI 2.103.3, Cloudflare 터널 실행기 2026.11.0이 들어 있습니다. Git 저장소 작업에는 운영체제에 Git이 설치되어 있어야 합니다. 내장 터미널의 **GitHub 로그인**을 누르면 자신의 계정을 브라우저로 인증합니다. 개발자 인증 정보는 설치 파일에 포함하지 않습니다.

형상관리에서 로컬 브랜치와 최근 커밋을 확인하고 프로젝트별 GitHub 원격 주소를 연결할 수 있습니다. **GitHub 현황 조회**를 누르면 해당 저장소의 변경 요청, 이슈, 자동 실행, 배포 환경을 불러옵니다. 변경 요청 상세에는 바뀐 파일, 리뷰 결정, 자동 검사 결과가 표시됩니다.

팀 배정안의 **역할별 Git 작업 폴더 사용**을 선택하면 첫 커밋이 있는 저장소에서 역할별 독립 브랜치를 만듭니다. 담당자가 끝낸 파일을 검토하고 선택해 커밋한 다음 통합 브랜치로 병합합니다. 충돌이 생기면 통합본 선택, 역할본 선택, 직접 수정 후 확인할 수 있습니다. 정리한 작업 폴더는 실행 기록에서 보존한 커밋으로 다시 엽니다. Git 작업 폴더와 참조는 사용하는 컴퓨터에 보관되며, 팀 대화와 산출물은 선택한 로컬 프로젝트 폴더에 보관됩니다.

개발 환경에는 Node.js 24 이상과 npm이 필요합니다.

```sh
npm ci
npm run dev
```

소스에서 개발 도구 번들까지 검증하려면 `npm run prepare:runtime`을 실행하세요. 공식 Node.js, GitHub CLI, Cloudflare 배포 파일을 내려받고 체크섬 목록 및 저장소에 고정한 SHA-256과 대조합니다. Mac과 Windows 설치 파일을 만들 때도 해당 운영체제용 도구를 준비합니다. [Node.js 배포 파일](https://nodejs.org/dist/v24.22.3/), [GitHub CLI 릴리스](https://github.com/cli/cli/releases/tag/v2.103.3), [Cloudflare 터널 릴리스](https://github.com/cloudflare/cloudflared/releases/tag/2026.11.0)

개발 실행기는 로컬 화면을 준비하고 Electron 창을 엽니다. `npm run dev:vite`는 브라우저에서 화면만 확인하는 명령입니다. 폴더 선택, 로컬 Codex 실행, 앱 업데이트는 데스크톱 창에서 확인합니다.

```sh
npm run check
node scripts/verify-downloads.mjs
```

`src/`는 화면, `electron/`은 운영체제와 Codex 연결, `shared/`는 데이터 형식, `docs/`는 공개 다운로드 페이지, `scripts/`는 검증과 빌드 도구입니다. 테스트에는 사용자 계정이나 개인 대화가 필요하지 않습니다. 실제 기기와 패키지로 확인한 범위는 [기능별 검증 기록](docs/FEATURES.md)을 참고하세요.

## 배포

Mac에서 `npm run dist:mac`, Windows에서 `npm run dist:win`을 실행하면 `release/`에 배포 파일이 생성됩니다. 저장소 배포의 대상은 Apple Silicon Mac과 Windows x64입니다. 배포용 아이콘은 사용자가 제공한 `Flow Icon.png`를 각 플랫폼 형식으로 변환한 파일입니다.

[터미널 설치기](docs/TERMINAL-INSTALL.md)는 릴리스 체크섬을 확인하고 기존 앱을 백업합니다. Windows에서는 기존 폴더를 복사한 뒤 파일 목록과 SHA-256을 검증하고, 원래 제거 프로그램을 유지한 상태로 새 설치를 실행합니다. 설치 실패 시 불완전한 앱은 별도로 보관하고 검증한 이전 앱을 복원합니다. 프로젝트와 대화 데이터는 삭제하지 않습니다.

GitHub Pages의 게시 원본은 GitHub Actions입니다. `pages.yml`이 `docs/`를 [다운로드 페이지](https://hyeondk.github.io/flowrium/)에 게시합니다. 최신 정식 공개 릴리스의 태그와 이름이 일치하는 설치 파일만 페이지에 연결합니다. Mac은 업데이트용 ZIP도 필요하고 모든 플랫폼에 SHA-256 목록이 필요합니다. 이전 0.1.x Mac 설치 파일은 현재 다운로드 대상에서 제외합니다.

공개 태그와 파일 이름은 `261114_01`처럼 날짜 버전을 사용하고 앞에 `v`를 붙이지 않습니다. Electron과 운영체제에 필요한 내부 숫자 버전은 별도로 매핑합니다. [버전 지정과 매핑](docs/VERSIONING.md), [릴리스 정의와 플랫폼별 검증](.github/workflows)을 참고하세요. 저장소를 옮기면 다운로드 페이지의 `docs/release-config.mjs`와 앱 업데이트 대상 저장소, 패키징의 `build.publish` 설정을 함께 확인하세요.

### Apple Silicon 맥 설치와 첫 실행

다운로드한 DMG를 열고 Flowrium을 응용 프로그램 폴더로 옮깁니다. Apple Developer ID 서명, 공증 여부는 해당 버전의 릴리스 설명에서 확인하세요. 미공증 버전은 첫 실행이 제한될 수 있습니다. 릴리스의 파일과 출처를 확인한 후 실행하려면 먼저 앱 열기를 시도한 다음 **시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기**에서 해당 앱을 허용합니다. [Apple의 앱 열기 안내](https://support.apple.com/ko-kr/102445)

### 키체인 암호 확인 창

`Flowrium Safe Storage` 키에 접근하려는 창은 앱에 보관한 초안, 연결 정보를 암호화하는 키의 접근을 macOS가 확인하는 것입니다. 일반적으로 **맥 사용자 로그인 암호**를 입력합니다. 로그인 키체인의 암호를 별도로 바꿨다면 그 키체인 암호를 사용합니다. 암호는 macOS 창에만 입력하며 채팅이나 앱의 일반 입력창에 전달하지 않습니다.

직접 설치하고 출처를 확인한 Flowrium이라면 **항상 허용**으로 해당 앱의 키 사용을 허용할 수 있습니다. 앱의 서명이나 설치 위치가 바뀌면 macOS가 다시 확인할 수 있습니다. 기존 암호화 자료를 유지하려면 이 키체인 항목을 삭제하지 마세요.

### 소스에서 직접 빌드하기

Apple 개발자 계정이 없어도 본인 맥에서 소스를 빌드해 사용할 수 있습니다. Node.js 24 이상과 Git이 설치된 Apple Silicon 맥의 터미널에서 실행하세요.

```sh
git clone https://github.com/hyeondk/flowrium.git
cd flowrium
npm ci
npm run dist:mac
open release
```

생성된 디스크 이미지에서 Flowrium을 응용 프로그램 폴더로 옮겨 여세요. 처음 실행한 뒤 자신의 ChatGPT 계정을 연결하고 프로젝트 폴더를 선택합니다. 이 방법은 각 사용자가 자기 컴퓨터에서 직접 생성하는 로컬 빌드입니다.

### Mac 서명과 공증 설정

저장소 관리자 계정으로 **Settings → Secrets and variables → Actions → Repository secrets**에 아래 값을 등록합니다. 인증서 파일, 개인 키, 암호는 저장소 파일이나 공개 릴리스에 넣지 않습니다.

| 비밀 값 이름 | 등록할 값 |
| --- | --- |
| `MAC_CSC_LINK` | 개인 키를 포함해 내보낸 Apple **Developer ID Application** 인증서(P12)의 Base64 값 |
| `MAC_CSC_KEY_PASSWORD` | P12를 내보낼 때 지정한 암호 |
| `APPLE_ID` | 공증에 사용할 Apple 개발자 계정 |
| `APPLE_APP_SPECIFIC_PASSWORD` | 위 계정에서 발급한 앱 전용 암호 |
| `APPLE_TEAM_ID` | 인증서를 발급한 Apple 개발 팀 식별자 |

배포 작업은 앱과 디스크 이미지의 서명, 공증, 설치 이미지와 업데이트 ZIP 안의 앱을 검사합니다. Developer ID 인증서가 없는 버전은 Apple 미공증 상태를 공개 릴리스에 명시합니다. 이 버전은 사용자가 설치 파일의 출처와 확인값을 확인한 뒤 수동으로 설치할 수 있습니다. Windows의 선택적 서명에는 `WIN_CSC_LINK`와 `WIN_CSC_KEY_PASSWORD`를 같은 위치에 등록합니다. [저장소 비밀 값 설정](https://github.com/hyeondk/flowrium/settings/secrets/actions)

Google 공용 로그인은 배포자 명의의 클라이언트 등록과 Google 공개 검증이 필요합니다. 현재 클라이언트 값은 비어 있으며, [배포 준비 안내](docs/GOOGLE-PUBLISHING.md)에서 실제 준비 상태와 설정 방법을 구분합니다. Dots는 공식 웹의 별도 로그인으로 사용하며 Flowrium 대화와 자동 동기화되지 않습니다.
