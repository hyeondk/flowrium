# 휴대폰 화면 검증

| 항목 | 확인한 동작 |
| --- | --- |
| 스켈레톤 | 초기 대시보드와 오늘 할 일, 최근 메시지 요청을 지연해 윤곽이 실제 내용으로 교체되는 것을 확인했습니다. |
| 느린 갱신 | 팀 조회가 갱신 주기보다 오래 걸려도 요청을 중복 실행하지 않습니다. 채팅을 읽는 동안 갱신 전후와 350밀리초 뒤 스크롤 위치는 410.85픽셀로 유지됐습니다. |
| 확인 바텀시트 | 320 / 390 / 768픽셀 화면에서 하단 중앙 정렬과 최소 44픽셀 터치 영역을 확인했습니다. 취소, 바깥 누르기, Esc 뒤 초점이 원래 버튼으로 돌아왔고 확인 전에는 작업이 중단되지 않았습니다. |
| 토스트 | 단순 처리 결과의 입장과 퇴장 모두 240밀리초이며 좌표는 유지되고 투명도만 변했습니다. |
| 정보 안내 | 휴대폰 설정의 도움말과 홈 화면 설치 안내는 중앙에서 열리고 닫힌 뒤 해당 설정 항목으로 돌아갑니다. |

합성 데이터로 모바일 브라우저의 실제 조작을 검사했습니다.

고정 스크롤바가 16픽셀인 화면에서는 도움말이 열릴 때 가로 중심이 8픽셀 어긋났습니다. 안내가 열린 동안 배경 스크롤을 잠그도록 수정한 뒤 같은 조건에서 가로와 세로 중심 오차가 각각 0.01픽셀 미만이었고, 닫으면 원래 화면을 다시 스크롤할 수 있었습니다.

확인 창을 취소한 뒤 2초 자동 갱신에서 원래 버튼이 교체되면 키보드 초점이 사라지는 현상도 재현했습니다. 수정 후 같은 작업의 버튼이 교체된 것을 확인하고 350밀리초를 더 기다려도 초점이 그 버튼에 유지됐습니다.

## 아이폰 화면

아이폰 17 시뮬레이터(iOS 27.0)의 웹 엔진에서 합성 대화를 열었습니다. 402 × 874 화면에서 시트와 화면 하단 사이의 간격은 0픽셀, 수평 중심 오차는 0픽셀이었습니다. 시트가 열리면 취소 버튼에 초점이 갔습니다. 취소한 뒤 다시 열어 확인했을 때 중단 요청이 정확히 한 번 전송됐습니다. 토스트의 입장과 퇴장 중 위치 이동은 없었고 불투명도는 각각 0에서 1, 1에서 0으로 변했습니다. [아이폰에서 열린 확인 창](mobile-confirmation-261115_08.png)

## 맥 설치본

애플 실리콘용 디스크 이미지와 압축 파일에 포함된 앱의 구성 항목 3,214개가 일치했습니다. 두 설치본의 코드 서명을 확인했습니다. 서명은 임시 서명이며 애플 공증은 받지 않았습니다. 별도 사용자 프로필로 앱을 실행하고 문서 생성, 본문 읽기와 터미널 입력을 확인했습니다. 설치본에 포함된 모바일 파일과 연결 처리 코드 12개가 검사한 소스와 일치했습니다.

단위 검사 357개가 모두 통과했습니다. 아이폰 시뮬레이터와 동시에 실행한 첫 검사에서는 프로세스 목록에 검사 프로세스가 포함되는지 확인하는 항목이 한 차례 실패했습니다. 시뮬레이터 종료 후 같은 소스에서 해당 항목 단독 검사와 전체 재검사가 모두 통과했습니다.

## 윈도우 설치본과 공개 다운로드

윈도우 64비트에서 모바일 화면, 중앙 도움말, 확인 창과 키보드 초점 복귀, 토스트를 검사했습니다. 단위 검사 357개 중 355개 통과, 운영체제 조건으로 2개 제외, 실패 0개였습니다. [윈도우 기능 검사](https://github.com/hyeondk/flowrium/actions/runs/43715699998/job/132816642332)

별도 윈도우 환경에서 기존 설치본을 수동으로 교체하고 프로젝트와 대화 초안을 복원했습니다. 같은 소스로 만든 이전 버전에서 앱 안의 업데이트 버튼을 눌러 새 버전으로 재시작하고 초안이 복원되는 것도 확인했습니다. [독립 설치 및 업데이트 검사](https://github.com/hyeondk/flowrium/actions/runs/43715699998/job/132820172481)

공개 파일 9개를 비로그인 상태에서 요청해 모두 다운로드 가능함을 확인했습니다. 각 파일의 크기와 SHA-256이 검증본과 일치했고, 소스 파일 513개의 내용이 배포 태그의 커밋과 일치했습니다. [파일별 검증 결과](validation/release-261115_08.json)
