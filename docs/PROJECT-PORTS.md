# 프로젝트 자동 포트표

프로젝트 설정의 **자동 포트표**에서 프로젝트 번호와 다섯 서비스 주소를 관리합니다. 처음 열면 다른 프로젝트와 외부 예약, 현재 실행 중인 로컬 서버를 확인하고 사용 가능한 번호를 배정합니다. 프로젝트 폴더는 사용자가 선택한 위치를 그대로 사용합니다.

| 서비스 | 계산 | 프로젝트 1번 | 프로젝트 99번 |
| --- | --- | --- | --- |
| 웹 / `web` | 2000 + 번호 | 2001 | 2099 |
| 관리자 / `admin` | 2100 + 번호 | 2101 | 2199 |
| API / `api` | 3000 + 번호 | 3001 | 3099 |
| 데이터베이스 / `db` | 4000 + 번호 | 4001 | 4099 |
| 보조 서버 / `aux` | 4100 + 번호 | 4101 | 4199 |

번호는 1~99, 직접 지정하는 포트는 1024~65535입니다. 한 프로젝트 안의 다섯 포트는 서로 달라야 합니다. 등록된 다른 프로젝트의 번호와 포트도 중복할 수 없습니다. **다음 빈 번호로 재배정**은 선택한 프로젝트만 바꿉니다. 다른 프로젝트의 기존 배정은 유지합니다.

**프로젝트 포트 배정** 스위치를 끄면 번호와 포트를 해제합니다. 다시 켜면 그 시점의 사용 가능한 번호를 배정합니다. 프로젝트 보관과 복원은 배정을 유지하므로 보관한 프로젝트의 번호를 자동으로 재사용하지 않습니다.

## 실제 사용 여부와 예약

검사는 인터넷 연결을 사용하지 않습니다. macOS와 Windows에서 IPv4 / IPv6 루프백, 전체 주소와 로컬 네트워크 인터페이스에 임시 TCP 바인딩을 시도한 뒤 즉시 닫습니다. 실행 중인 서비스에 연결하거나 데이터를 보내거나 프로세스를 종료하지 않습니다. 주소 체계가 비활성화됐거나 권한과 시스템 제외 포트 때문에 확인하지 못하면 화면에 표시합니다. 확인 불가 상태를 빈 포트로 간주해 자동 배정하지 않습니다.

사용 여부는 검사 시점의 결과이며 포트표 저장 후 운영체제의 포트를 계속 점유하지 않습니다. 다른 프로그램이 나중에 같은 포트를 열 수 있으므로 서비스 실행 전에 다시 검사하세요. 실제 서비스의 실행 명령이나 환경 파일을 자동으로 수정하지 않습니다. 주소 복사와 환경변수 복사 기능으로 필요한 설정을 전달할 수 있습니다.

내가 이미 실행한 서버를 등록하려면 번호와 포트 직접 설정에서 **이미 실행 중인 서버 포트 사용**을 켜고 저장하세요. 다른 프로젝트의 배정이나 외부 예약은 이 옵션으로 덮어쓸 수 없습니다.

외부 예약 포트는 `5000, 6000-6010`처럼 숫자와 범위로 지정하며 최대 4096개입니다. 자동 배정에서 제외하는 설정이며 운영체제 방화벽이나 실행 중인 서비스의 포트를 변경하는 기능은 아닙니다. 프로젝트에 이미 배정된 포트는 해당 프로젝트를 재배정한 뒤 예약하세요.

## 보존과 이관

- 프로젝트 번호와 포트는 선택한 프로젝트 폴더의 `.flowrium/ports/`에 개정별로 저장합니다. 첫 기록은 `first.json`, 다음 기록은 이전 개정 식별자 이름의 파일이며 기존 기록을 덮어쓰지 않습니다.
- 앱 데이터 폴더의 `project-ports.json`에는 외부 예약 포트를 저장합니다. 예약을 변경하면 기존 설정을 `project-ports-backups/`에 보존합니다.
- 여러 창과 프로세스가 같은 앱 데이터에서 배정하면 `project-ports.lock`과 개정 검사를 통해 순차 처리합니다. 오래된 화면에서 저장하면 새로고침을 요청합니다. 알 수 없는 잠금 파일과 충돌한 기록, 심볼릭 링크는 덮어쓰지 않습니다.
- 같은 프로젝트 폴더를 다시 연결하면 기존 배정을 읽습니다. 전체 자료 이관은 프로젝트 개정 기록과 예약 설정도 포함합니다. 서로 다른 자료를 합칠 때 번호가 겹치면 원본을 보존하고 충돌을 검토해야 합니다.
- 계정 변경, 잠금, 로그아웃, 업데이트 설치 또는 앱 종료가 시작되면 진행 중인 검사 결과로 새 배정을 저장하지 않습니다. 종료 시 진행 중인 포트 작업이 마무리될 때까지 기다립니다.

## 검증

`node --test tests/project-ports.test.cjs`는 계산, 영속 보존, 예약과 수신 충돌, 번호 고갈, 직접 지정, 개정 충돌, 분리 프로세스 동시 배정, 보관과 복원, 다른 프로필 재연결, 손상 기록 보존, 이관 사전 검사, 종료와 계정 전환, 실제 IPv4 / IPv6 소켓을 검사합니다.

`node tests/project-ports-e2e.cjs`는 별도 프로필의 실제 앱에서 포트표 표시, 주소와 환경변수 복사, 숫자 입력의 스크롤 안정성, 사용자 지정, 수신 충돌 처리, 외부 예약, 재배정, 배정 스위치와 재시작 보존을 검사합니다. 검증용 앱과 임시 프로젝트는 종료 후 정리합니다.
