# 날짜 버전

Flowrium의 공개 버전은 `YYMMDD_순번`입니다. 예를 들어 서울 날짜 2026년 11월 14일의 첫 배포는 `261114_01`, 같은 날 다음 배포는 `261114_02`입니다. 다음 날은 `261115_01`부터 시작합니다. 순번은 `01`~`99`이며 날짜를 임의로 앞당기지 않습니다.

앱의 버전 표시 / GitHub 릴리스 태그 / 다운로드 페이지 / 설치 파일 이름 / 소스 묶음에 같은 공개 버전을 사용합니다. 날짜 태그 앞에 `v`를 붙이지 않습니다.

```text
261114_01
Flowrium-261114_01-mac-arm64.dmg
Flowrium-261114_01-mac-arm64.zip
Flowrium-261114_01-win-x64.exe
Flowrium-261114_01-source.tar.gz
```

## 버전 지정

```sh
npm run release:version -- 261114_02
```

`20261114` 또는 `261114`를 지정하면 해당 날짜의 `_01`을 설정합니다. 인자를 생략하면 서울 날짜를 기준으로 같은 날의 순번을 올리거나 새 날짜의 `_01`을 지정합니다. `package.json` / 잠금 파일 / 설치 파일 이름 / Windows 설치기 표시는 함께 바뀝니다. 이 명령은 로컬 파일만 바꾸며 GitHub에 게시하지 않습니다.

## 기존 버전에서 전환

기존 `0.6.0` 이하의 업데이트 코드는 숫자 버전 태그만 인식합니다. 이미 설치된 코드를 서버 메타데이터만으로 바꿀 수 없으므로 날짜 버전으로 전환할 때는 이번 한 번 [다운로드 페이지](https://hyeondk.github.io/flowrium/)에서 새 설치본을 직접 받아 설치합니다. 프로젝트와 대화는 보존하고 기존 앱을 백업하는 [터미널 설치기](TERMINAL-INSTALL.md)도 사용할 수 있습니다.

날짜 버전부터는 날짜와 순번을 비교해 새 버전을 확인합니다. Windows는 다운로드 / 검증 / 설치 / 재시작을 진행합니다. Mac의 앱 내 교체는 새 앱의 Developer ID 서명과 Apple 공증을 확인해야 하며, 미공증 배포본은 수동 설치를 안내합니다. 이 형식 변경은 운영체제의 보안 판단을 해제하지 않습니다.

## 내부 패키지 번호

Electron과 운영체제의 파일 정보는 숫자로 된 패키지 번호를 요구합니다. 이를 위해 공개 `261114_01`을 내부 `26.11.1401`로 일관되게 매핑합니다. 마지막 숫자는 `일 × 100 + 순번`입니다. 제품 화면에는 공개 버전을 표시하고 설치 파일·기동 확인·교체 검증에는 해당 내부 번호를 사용합니다.

업데이트 검사는 기존 숫자 버전의 조회도 지원하지만 새 공개 태그는 날짜 형식만 사용합니다. 유효하지 않은 날짜 / `00` 순번 / 경로가 섞인 값 / 다른 릴리스 주소 / 중복 파일은 거절합니다. 배포 파일과 소스 묶음의 버전·크기·SHA-256을 확인한 뒤 실행합니다.
