# 전체 자료 이관

설정의 **전체 자료 이관**에서 자료를 내보내거나 가져올 수 있습니다. 원본은 읽기만 하며 새 프로젝트 폴더에 사본을 만듭니다. 적용 전 백업 / 파일 검증 / 실패 시 되돌리기 / 중복 적용 확인 / 이관 결과와 원문 보관을 제공합니다.

## 보존하는 자료

| 자료 | 보존 방식 |
| --- | --- |
| 프로젝트 대화 | 본문 / 메시지 시각 / 개정과 삭제 이력 / 업무 정보 / 좋아요를 보존합니다. |
| 첨부 | 파일 바이트 / 파일 이름 / 종류 / 크기 / SHA-256을 보존합니다. |
| 실행 도구 기록 | 원문 파일을 보관합니다. 다른 형식의 도구 입력과 출력 / 승인 / 실행 결과는 읽을 수 있는 대화 기록으로도 변환합니다. |
| 기억 | 프로젝트 기억 개정 전체 / 개인 기억을 보존합니다. 다른 형식의 기억은 개인 기억으로 추가하며 자동 연결하지 않습니다. |
| 프로젝트 설정 | 상세 정보 / 목표 / 체크리스트 / 저장소 / 서비스 설정 / 팀 이력 / 포트표 등 프로젝트 기록 폴더 전체를 보존합니다. |
| 개인 대화 | 내보내는 시점의 현재 계정에 속한 일반 대화 / 통합 채팅을 옮깁니다. 가져올 때 현재 계정의 기존 대화에 추가합니다. |
| 앱 설정 | 앱 기본 설정 / 현재 계정 초안 / 업무 연결 기록 / 예약 포트 / 음악 / 음성 공개 설정을 선택해 적용합니다. 실행 파일 경로와 인증은 다시 연결합니다. |
| 작업 파일 | 선택한 경우 프로젝트의 소스와 문서도 함께 복사합니다. |

**기록 보존과 새 AI 실행 연결은 서로 다릅니다.** 다른 엔진의 숨겨진 실행 문맥 / 원격 세션 / 되감기 지점 / 미완료 도구 실행을 Codex 실행 문맥으로 복원하지 않습니다. 이전 엔진 식별자와 원문은 보관하고 활성 대화에서는 실행 연결을 제거합니다. 옮긴 본문을 확인한 뒤 새 요청을 시작합니다. 원래 도구를 자동 재실행하거나 원래 승인에 동의한 것으로 처리하지 않습니다.

## 사용 순서

1. 원본 기기에서 **현재 자료 내보내기 미리보기**를 선택합니다. 기본값은 앱 기록과 첨부이며 **프로젝트 작업 파일도 포함**을 선택하면 작업 파일을 함께 넣습니다.
2. 파일 수와 크기 / 경고 / 제외 목록을 확인하고 저장할 폴더를 선택합니다. 생성되는 `Flowrium-transfer-<식별자>` 폴더 전체를 대상 기기로 옮깁니다.
3. 대상 기기에서 본인 계정으로 로그인합니다. **원본 자료 폴더**에서 묶음 폴더를 선택한 뒤 **가져올 자료 미리보기**를 누릅니다.
4. 가져올 프로젝트와 개인 대화 공간을 선택하고 프로젝트를 보관할 대상 폴더를 지정합니다. 필요하면 프로젝트마다 다른 상위 폴더를 선택합니다.
5. 같은 원본 프로젝트가 이미 연결되어 있으면 **새 식별자로 사본 만들기** 또는 **같은 프로젝트 건너뛰기**를 선택합니다. 기존 프로젝트 폴더를 덮어쓰지 않습니다.
6. **기억과 앱 설정 / 초안 / 업무 연결 기록도 적용** 여부를 확인합니다. 해당 앱 설정은 현재 값을 백업한 뒤 바꿉니다. 개인 기억은 새 식별자로 추가합니다.
7. **백업 후 이 계획 적용**을 누릅니다. 실행 중인 작업을 마쳐야 적용할 수 있습니다. 적용 후 **Flowrium 다시 시작**을 누릅니다.
8. **이관 결과와 보존 원문**에서 성공 / 실패 / 복구 결과와 변환 전 원문을 확인합니다.

폴더형 프로젝트 카드와 대화 상태 자료를 사용하는 다른 로컬 형식도 읽을 수 있습니다. `data/projects/*.md`와 `data/state/chats.json`이 있는 앱 폴더를 원본으로 선택합니다. 작업 파일까지 옮기려면 원본 작업 공간을, 기억을 옮기려면 원본 기억 폴더를 따로 선택합니다. 카드 본문과 설정 / 대화 인덱스 / 도구와 승인 / 첨부 원문 / 비인증 상태 자료도 원문 보관에 남깁니다. 현재 화면에서 표현할 수 없는 사용자 설정도 원문으로 보존하며 같은 기능이 자동으로 활성화되었다고 표시하지 않습니다.

## 제외와 제한

- 계정 로그인 토큰 / 키체인 비밀 / 암호 / 인증서 / 비밀 키 / 잠금 정보 / 암호화한 음성 환경변수 값은 내보내지 않습니다. 파일 이름과 설정 키에서 제외한 항목을 미리보기에 표시합니다. 대화 본문과 일반 문서에 사용자가 직접 적은 민감한 내용은 문서 내용으로 남을 수 있으므로 공유 전에 확인하세요.
- 저장소의 `.git` / 설치 의존성 / 가상환경 / 일부 실행 캐시는 작업 파일 복사에서 제외합니다. 제외 목록을 확인하세요. 앱의 인증 / 모델 / 설치 의존성을 배포 묶음에 넣지 않습니다.
- 심볼릭 링크 / 특수 파일 / 폴더 밖 경로 / Windows에서 사용할 수 없는 이름 / 대소문자나 유니코드 정규화가 충돌하는 경로는 조용히 누락하지 않고 이관을 중단합니다.
- 한 번에 파일 100,000개 / 전체 8GB / 파일 한 개 512MB까지 지원합니다. 큰 프로젝트는 나누어 옮깁니다.
- 다른 형식의 첨부가 현재 첨부 제한을 넘거나 이름이 호환되지 않으면 원문 바이트를 보관하고 경고합니다. 화면의 긴 본문과 기억도 표시 제한이 있으면 원문 전체를 함께 보존합니다.
- 프로젝트 번호나 포트가 기존 프로젝트 / 사용자 예약 / 같은 묶음과 충돌하면 가져온 사본의 포트 배정을 비활성화하고 경고합니다. 원래 개정과 번호는 원문에 보존합니다. 실제 사용 중인 포트 확인 결과는 기기와 확인 시각에 따라 달라집니다.
- 실행 중이던 전달과 요청은 보류합니다. 예약 알림은 취소 상태로 복원하고 업무 자동화는 끕니다. 음성 서버는 직접 시작해야 하며 환경변수 값은 다시 입력해야 합니다. 서비스 명령도 직접 검토한 뒤 실행합니다.
- 다른 운영체제의 외부 파일 / 음악 / 음성 실행 파일 경로는 자동으로 다운로드하거나 설치하지 않습니다. 선택한 프로젝트 안의 경로는 새 대상 경로로 연결하고 외부 경로는 다시 확인합니다.

## 저장 형식과 복구

이관 묶음은 `manifest.json`과 내용 해시로 이름을 붙인 `objects/`로 구성됩니다. 모든 파일은 크기와 SHA-256을 검증합니다. 기존 파일을 덮어쓰는 압축 해제 기능을 사용하지 않습니다. 이관 원문은 앱 데이터의 `migration-records/<식별자>/source/`에 보존하며 같은 위치의 `receipt.json`에서 결과를 확인할 수 있습니다.

적용 전 원본과 대상 상태를 다시 확인합니다. 대상 변경과 백업 / 적용 경로는 `transaction.json`에 기록합니다. 실패 시 생성한 사본을 제거하고 등록 정보 / 앱 설정 / 기존 개인 대화를 되돌립니다. 적용 도중 앱이 종료되면 다음 기동에서 중단 기록을 확인하여 먼저 되돌립니다. 복구가 끝나지 않으면 정상 실행을 막고 결과와 백업 경로를 안내합니다. 백업과 원문은 자동 삭제하지 않습니다.

동일 묶음 / 선택 / 대상 매핑 / 설정 범위의 적용을 다시 요청하면 완료한 결과를 반환해 중복으로 만들지 않습니다. 새 대상 폴더를 지정해 의도적으로 별도 사본을 만들 수 있습니다.

검증에는 개인 자료를 사용하지 않습니다. 합성 프로젝트 / 현재 계정과 다른 계정의 대화 / 첨부 / 도구 이력 / 비밀값이 섞인 설정 / 쓰기 실패 / 프로세스 중단 / 경로 공격을 사용해 보존과 복구를 검사합니다. 실제 사용자 자료 이관은 사용자가 미리보기를 검토한 뒤 실행합니다.
