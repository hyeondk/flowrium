# Codex 프로젝트 대화 연결

이 기기에 저장된 Codex 프로젝트 대화를 찾아 Flowrium에 연결할 수 있습니다. 기본값은 **같은 대화로 연결**이며 원래 `threadId`를 유지해 기존 문맥으로 이어갑니다. 원래 과거 메시지를 삭제하거나 이동하지 않습니다.

설치 파일별 검사 결과와 사용 조건은 [261115_04 검증 기록](VALIDATION-261115_04.md), [전환 상태](REPLACEMENT-STATUS.md), [날짜 버전과 설치 전환](VERSIONING.md)에서 확인하세요. 개인 대화 연결은 각 사용자의 기기에서 실행합니다.

Flowrium은 먼저 설치된 ChatGPT 또는 Codex 앱을 확인합니다. Flowrium을 켜 둔 채 나중에 데스크톱 앱을 설치해도 자동으로 다시 확인하고, 같은 운영체제 사용자에게 이미 공유된 Codex 로그인으로 연결할 수 있습니다.

## 연결하기

1. 본인의 ChatGPT 계정으로 로그인하고 진행 중인 작업을 마칩니다.
2. **설정 → 계정과 모델 → Codex 대화와 프로젝트 불러오기**를 엽니다. 업무 연결의 자료 관리에서도 열 수 있습니다.
3. **불러올 대화와 프로젝트 찾기**를 누르고 프로젝트 / 대화 제목 / 메시지와 첨부 정보 / 경고를 확인합니다. 과거 다른 계정의 로컬 기록은 자동으로 소유자를 식별할 수 없으므로 본인 대화만 선택하세요.
4. 가져올 프로젝트와 대화를 선택해 적용합니다. 대화를 선택하지 않고 프로젝트 폴더만 등록할 수도 있습니다. 대화는 **같은 대화로 연결** 또는 **독립 사본 만들기**로 가져올 수 있습니다.
5. 연결 기록에서 **대화 열기**를 누릅니다. **보관 원문**으로 이 기기에 저장한 원문을 확인할 수 있습니다.

현재 기기의 Codex가 제공하는 프로젝트 대화를 조회합니다. 다른 기기나 ChatGPT 웹의 모든 대화 목록을 가져오는 기능은 아닙니다. 프로젝트 폴더를 찾을 수 없거나 읽지 못한 대화는 오류를 표시하므로 결과를 확인하고 필요한 항목만 다시 처리하세요.

## 두 가지 방식

| 구분 | 같은 대화로 연결 / 기본값 | 독립 사본 만들기 |
| --- | --- | --- |
| 내부 대화 | 원래 `threadId` 유지 | 새 대화 식별자로 분기 |
| 새 요청 | 원래 대화에 이어 기록 | 사본에 기록 |
| 양쪽 변경 | 연결된 대화의 요청과 공개된 답변을 자동 반영 | 원래 대화와 별개로 진행 |
| 분기 / 되감기 / 압축 | Flowrium에서 제한 | 사본에서 사용 가능 |
| 적합한 경우 | 두 앱을 번갈아 사용 | 원래 대화를 보존하고 별도 작업 |

원래 대화가 실행 중이면 연결한 화면에서 즉시 새 작업을 시작하지 않습니다. 열린 대화는 작업 완료를 다시 확인해 새 답변을 표시합니다. 실행 중인 원본의 독립 사본은 마지막으로 완료한 작업까지 분기하며, 완료한 작업이 아직 없으면 복사를 보류합니다.

## 양쪽 앱에서 이어 쓰기

앱이 연결돼 있으면 약 4초 간격으로 최근 변경과 진행 중인 대화를 우선 확인하고, 다른 연결 대화도 차례로 확인합니다. 화면에서 선택하지 않은 대화의 요청, 원본에 기록된 중간 답변과 최종 답변도 수신합니다. 선택한 대화는 창에 돌아오면 다시 확인하며 **대화 새로고침**으로 직접 확인할 수 있습니다. 기록량과 연결 상태에 따라 반영 시간이 달라집니다.

등록한 폴더에서 같은 계정으로 새로 시작한 Codex 대화는 첫 요청이 기록되면 프로젝트 목록에 자동으로 나타납니다. 앱이 꺼진 사이 생성한 대화도 기기와 계정이 같고 이전에 연결한 공식 프로젝트 식별자가 일치하면 다시 열 때 찾아옵니다. 계정을 확인할 수 없는 과거 로컬 기록은 **프로젝트 대화 연결**에서 직접 선택하세요.

Flowrium에서 새로 실행한 프로젝트 대화 / 일반 대화 / 통합 대화도 같은 기기의 Codex 대화 식별자를 사용합니다. 기존에 Flowrium에서 만든 대화는 이 버전에서 한 번 이어 쓴 뒤 자동 연결됩니다. 사용자가 보낸 본문과 앱의 참고 자료를 분리하므로 새 요청은 상대 앱에서도 입력한 문장으로 보입니다. 이전 버전에서 보낸 원래 기록은 그대로 유지됩니다.

**대화 자동 동기화 → 데스크톱에서 이 대화 이어가기**를 누르면 같은 기기에서 연결한 원래 Codex 대화가 열립니다. 두 앱을 켜 둔 채 어느 쪽에서든 같은 대화를 읽을 수 있습니다. [데스크톱 대화 링크](https://learn.chatgpt.com/docs/reference/commands)

Codex가 해당 대화의 작성 권한을 사용하고 있으면 Flowrium은 입력을 보관합니다. 32,000자 이하의 글과 첨부 사진은 **추가 지시 → Codex 대화 설정으로 보내기**를 선택하면 Codex를 열어 둔 채 원래 대화에 작업을 맡길 수 있습니다. 확인 창에는 원래 대화의 모델 / 파일 접근 권한 / 승인 설정이 적용된다는 안내가 표시됩니다. 대화가 작업 중이면 기존 작업이 끝난 뒤 이어집니다. **Codex에서 실행 대기**는 원래 앱이 요청을 접수했다는 뜻입니다. 실행 전에는 대기열에서 취소할 수 있습니다.

Flowrium에서 보낸 요청은 Flowrium에서 선택한 모델과 작업 권한을 사용합니다. 다른 앱이 같은 대화의 작성 권한을 갖고 있으면 취소할 수 있는 추가 지시로 보관하고, 권한이 반환되는 대로 같은 대화에 전송합니다. 일반 대화 / 통합 채팅 / 프로젝트 대화에 이 동작을 적용합니다. 문서 첨부와 긴 원문도 이 경로에서 이어집니다. [Codex 앱 서버](https://learn.chatgpt.com/docs/app-server) / [원래 대화의 대기열](https://learn.chatgpt.com/docs/developer-commands?surface=cli#codex-queue)

실제 로그인 계정에서 시험용 대화를 두 앱이 세 차례 이어 쓴 뒤, 공식 데스크톱의 대화 읽기 기능으로 같은 대화를 다시 조회했습니다. 세 차례의 기록과 Flowrium에서 입력한 내용을 기억한 마지막 답변을 확인했습니다. 별도로 모의 모델을 연결한 두 Codex 프로세스로 열린 Flowrium 화면에 새로고침 버튼 없이 답변이 표시되는지 시험했습니다. 이미 보고 있는 ChatGPT 데스크톱 화면이 스스로 다시 그려지는 시점은 해당 앱이 결정합니다. 일반 ChatGPT 웹 계정의 채팅 목록에 이 로컬 기록을 자동으로 생성하거나 백그라운드에서 모든 대화를 복제하는 공개 연동 방식은 확인되지 않았습니다.

## 프로젝트와 대화 이름

**프로젝트 설정 → 킥오프 수정 → 프로젝트 이름**에서 표시 이름을 바꿀 수 있습니다. 같은 기기의 Codex에 같은 폴더가 하나의 프로젝트로 등록돼 있으면 어느 쪽에서 이름을 바꿔도 함께 반영됩니다. Flowrium에만 등록된 폴더는 연결 상태에서 이름을 처음 바꿔 저장할 때 Codex 프로젝트로 등록합니다. 이미 연결한 프로젝트는 오프라인에서 바꾼 이름을 보관해 두었다가 같은 계정으로 재연결하면 전송합니다. 연결이 끊긴 사이 양쪽 이름이 모두 바뀌었으면 프로젝트 설정에서 최종 이름을 입력해 저장하세요.

여러 폴더가 하나의 Codex 프로젝트를 구성하거나 같은 폴더가 중복 등록되면 Flowrium의 개별 카드 이름을 관리합니다. 프로젝트 이름 옆에 연결 상태와 사유가 표시됩니다. 새 폴더가 Codex 사이드바에 보이지 않으면 Codex에서도 같은 폴더를 한 번 여세요. 데스크톱 사이드바는 앱 서버의 등록 목록과 다를 수 있습니다. 실제 폴더 경로는 유지합니다. Codex의 프로젝트 목록에 나오지 않는 기기 전용 폴더 별칭은 확인할 수 없습니다. 이 기능은 번들 Codex 앱 서버의 실험적 프로젝트 관리 규격을 사용합니다. 프로젝트 관리 기능이 없는 Codex에서는 Flowrium의 프로젝트 이름과 연결된 대화의 제목을 각각 관리할 수 있습니다.

실제 두 앱을 열어 점검했을 때 Codex에서 바꾼 프로젝트 이름은 Flowrium에 반영됐습니다. 반대 방향에서는 Flowrium에서 바꾼 이름이 Codex의 프로젝트 기록에 저장된 뒤에도 Codex 사이드바에 이전 이름이 남는 경우가 있었습니다. 프로젝트 등록을 삭제한 뒤에도 사이드바에 기존 폴더가 남을 수 있습니다. 작업 폴더의 파일은 그대로 유지됩니다.

Codex에 등록한 프로젝트 이름과 데스크톱 사이드바의 표시 이름은 따로 갱신될 수 있습니다. 시험에서는 Flowrium에서 바꾼 이름이 Codex의 원본 프로젝트에 저장된 뒤에도 열려 있던 데스크톱 사이드바 목록에 이전 이름이 남았습니다.

**대화 관리 → 이름 저장**은 원본에 연결된 채팅의 이름을 양쪽에 반영합니다. 응답을 받는 도중이나 요청이 작성 권한을 기다리는 동안에도 제목을 바꿀 수 있습니다. 첫 요청을 시작하며 정한 이름은 첫 작업이 접수되면 원본에 저장됩니다. 상대 앱에서 이름을 바꾸면 앱에 돌아왔을 때와 주기적인 목록 갱신 때 제목을 다시 읽습니다. [Codex 앱 서버의 대화 관리](https://learn.chatgpt.com/docs/app-server)

## 기록과 첨부 보관

일반적인 길이의 요청은 원문을 그대로 보냅니다. 32,000자를 넘으면 Flowrium은 원문을 로컬에 보관합니다. 새 프로젝트 / 일반 / 통합 대화의 모델은 그 요청에 첨부된 글을 전용 도구로 나누어 읽습니다. 운영체제의 명령 실행 권한은 필요하지 않습니다. 상대 앱의 같은 대화에는 원문 참조가 표시될 수 있습니다. 200만자를 넘는 입력은 원문 첨부로 보관합니다. 20MiB를 넘더라도 사용자가 나눠 보낼 필요가 없습니다. 휴대폰에서는 원문을 작은 조각으로 전송하고 컴퓨터가 전체 무결성을 확인한 뒤 요청 한 건을 접수합니다. 모델이 한 번에 처리할 수 있는 분량은 선택한 모델의 문맥 범위에 따릅니다. 이모지 등 일부 문자는 길이 계산에서 두 자리로 셉니다.

전용 도구를 제공하지 않는 기존 대화에서는 같은 계정의 모델이 원문을 부분별로 정리한 뒤 같은 대화에서 답합니다. 이 방식은 추가 모델 호출이 발생하고 정리 과정에서 세부 표현이 달라질 수 있습니다. 모델의 문맥, 사용량, 네트워크 상태는 실제 응답 범위와 시간에 영향을 줍니다.

| 자료 | 처리 범위 |
| --- | --- |
| 사용자와 AI 본문 | 전체 조회한 대화의 표시 가능한 본문 보관 / 갱신 시 중복 방지 |
| 도구 기록 | 명령 실행 / 파일 변경 / 도구 호출을 표시 가능한 기록으로 변환 |
| 원문 | 조회한 대화와 항목의 원문을 프로젝트의 `.flowrium/codex-source/`에 로컬 보관 |
| 첨부 | 원래 정보와 파일 참조를 원문에 보존 / 확인 가능한 지원 로컬 이미지 추가 복사 |
| 사라진 임시 이미지 | 공식 원본 기록과 명시된 이전 기록에서 사용자 본문 / 첨부 경로 / 수와 순서가 같은 이미지 사본을 복구 / 후보가 다르면 보류 |
| 읽지 못한 첨부 | 경고와 원문 참조 보존 / 원격 자동 다운로드나 모든 파일의 원본 복사는 보장하지 않음 |
| 연결 결과 | 적용 / 갱신 / 건너뜀 / 실패를 대화별로 기록 |

임시 원본이 없어 기록에서 복구한 이미지는 **대화 기록의 사본**입니다. 모델 입력 과정에서 해상도나 인코딩이 바뀌었을 수 있으므로 원래 파일과 같은 바이트라고 보장하지 않습니다. 출처와 SHA-256을 로컬 첨부 정보에 보관합니다. 원본과 기록 사본을 모두 찾지 못하면 참조와 경고를 남깁니다. 부족한 첨부는 대화를 다시 찾아 연결하면 메시지를 중복 생성하지 않고 재확인합니다.

원문 / 첨부 / 계정 정보 / 개인 대화는 공개 설치본과 소스 배포 묶음에 넣지 않습니다. 사용자 프로젝트를 별도로 공개할 때도 `.flowrium/`이 포함되지 않도록 확인하세요. 연결은 원래 계정과 기기를 확인하며, 다른 기기로 폴더만 복사한 뒤 원래 대화를 실행하거나 갱신할 수는 없습니다.

긴 기록은 작은 페이지로 나누어 조회하며 큰 응답은 묶음을 줄여 다시 읽습니다. 변경 없는 백그라운드 갱신은 전체 본문을 다시 가져오지 않고, 수동 갱신과 실행 전에는 전체 내용을 대조합니다. 표시 대화는 저장 표현 기준 120MiB까지 지원하고 원문은 별도 보관합니다. 화면에는 최근 기록부터 표시하며 **이전 메시지 100개 더 보기**로 과거 기록을 이어 볼 수 있습니다.

## 연결된 항목 삭제와 복원

같은 계정과 기기에 연결한 대화는 Flowrium과 Codex 양쪽에서 보관과 복원을 반영합니다. 원본이 영구 삭제되었음을 확인하면 Flowrium은 로컬 대화를 휴지통으로 옮깁니다. 이때 복원하면 독립 사본을 열 수 있습니다. 같은 폴더로 확인된 프로젝트는 작업 폴더를 유지하면서 양쪽 목록 등록을 해제하거나 복원할 수 있습니다. [삭제와 휴지통](DELETION.md)

## 실행 제약

- 원래 대화의 지침과 실행 문맥을 유지합니다. 모델 / 생각의 깊이 / 작업 모드는 Flowrium에서 선택할 수 있습니다.
- 원래 앱 전용 동적 도구나 추가 입력은 Flowrium에서 처리할 수 없는 경우가 있습니다. 필요한 작업은 원래 앱에서 이어가거나 Flowrium의 새 업무 대화를 사용하세요.
- 연결 대화는 원본 보호를 위해 Flowrium에서 분기 / 되감기 / 수동 압축 / 자동 압축을 제한합니다. 이 기능이 필요하면 설정에서 독립 사본을 만드세요.
- 계정 전환 / 잠금 / 기기 불일치 / 진행 중인 실행에서는 해당 작업을 거절하거나 갱신을 보류합니다. 표시된 안내를 해결한 뒤 다시 확인하세요.

## 기존 가져오기와의 차이

**작업 기록 → Codex 기록 가져오기**는 프로젝트 경로에 맞는 사용자 메시지와 답변 본문을 한 번 복사하는 기존 기능입니다. 이후 자동 갱신 / 전체 도구 기록 / 첨부 원본 / 원래 실행 문맥 연결은 그 기능의 범위가 아닙니다.

**전체 자료 이관**은 지원하는 자료 묶음의 프로젝트 / 설정 / 기억 / 초안 등을 옮기는 별도 절차입니다. 원래 Codex 대화를 같은 식별자로 이어 쓰려면 이 문서의 **프로젝트 대화 연결**을 사용하세요. [전체 자료 이관](MIGRATION.md)

기존 앱의 삭제는 필요한 대화 / 첨부 / 도구 / 외부 연결 / 백업을 확인한 뒤 결정하세요. 연결 완료만으로 모든 기능의 동일성이나 개인 자료 전체의 이관 완료를 뜻하지 않습니다.
