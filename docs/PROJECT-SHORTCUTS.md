# 프로젝트 바로가기와 저장소 업무 완료

프로젝트 홈의 **프로젝트 바로가기**에서 운영 주소 / 로컬 폴더 / Drive 폴더를 바로 엽니다. 추가와 이름 변경 / 제거는 프로젝트 설정에서 합니다. 바로가기 제거는 연결 정보만 지우며 실제 파일이나 외부 자료는 지우지 않습니다.

## 폴더와 이관

- 로컬 폴더는 기본 폴더 선택 창에서 직접 고릅니다. 프로젝트 내부는 상대경로로 보관하고 외부는 이 기기의 절대경로로 보관합니다.
- 다른 위치로 프로젝트 자료를 이관하면 내부 바로가기는 새 프로젝트를 기준으로 해석합니다. 대상 폴더가 포함되지 않았거나 비어 있어서 복사되지 않았다면 새 위치의 폴더를 다시 골라 주세요.
- 외부 절대경로는 이관하거나 카드로 가져올 때 위치 정보만 보존하고 열기를 비활성화합니다. 같은 주소가 다른 기기의 다른 자료를 가리키는 일을 피하도록 새 기기에서 다시 선택해야 합니다.
- 다른 위치를 가리키는 심볼릭 링크 / 없어진 폴더 / 잠금이나 계정 전환 도중의 선택 결과는 사용할 수 없습니다. 새 로컬 위치는 직접 선택한 결과만 저장합니다.
- 운영 주소는 계정 정보가 포함되지 않은 `http` 또는 `https` 주소만, Drive는 `drive.google.com`의 공식 폴더 주소만 허용합니다. Flowrium이 해당 서비스의 로그인이나 폴더 접근 권한을 대신 부여하지 않습니다.

## 저장소 실행 후 업무 완료

형상관리의 **여러 저장소 통합 실행과 안전한 정리**에서 실행 단계를 **병합 후 연결 업무 완료**로 선택합니다. 완료할 프로젝트 업무를 지정하고 변경 요청 내용을 입력한 뒤 실행 계획을 검토합니다. 계획에는 연결 업무 이름 / 계획 상태 / 현재 상태를 함께 표시합니다.

모든 선택 저장소의 커밋 / 푸시 / 변경 요청 생성 / 병합 단계가 성공한 뒤 연결 업무를 완료합니다. 연결 대상이 없거나 다른 프로젝트의 업무이거나 실행 중 / 대기 지시가 있는 경우에는 완료하지 않습니다. 계획 이후 업무가 변경되면 계획을 다시 만들어야 합니다. 병합 실패 시에는 연결 업무를 완료하지 않고 실패 단계와 이미 실행한 단계를 보존합니다.

완료 시에는 실행 기록 식별자 / 완료 시각 / 커밋 근거를 업무에 보관하며 실행 계획에서도 실제 완료 상태를 확인할 수 있습니다. 외부 저장소는 현재 기기의 폴더 접근 연결이 유효해야 실행할 수 있습니다.

## 검증 범위

`tests/project-shortcuts.test.cjs`는 합성 프로젝트의 주소 검증 / 실제 폴더 선택 결과 / 계정 및 잠금 변경 / 선택 결과 재사용 차단 / 재시작 / 제거 시 원본 보존 / 전체 이관과 카드 가져오기를 검사합니다. `tests/repository-flow.test.cjs`는 로컬 Git 원격과 모의 GitHub 응답으로 실제 계획 / 다중 저장소 병합 순서 / 업무 상태 변경 / 실패와 재개를 검사합니다.

화면 검사는 `tests/project-shortcuts-e2e.cjs`와 `tests/repository-completion-e2e.cjs`에 있습니다. 후자는 실제 로컬 Git과 기존 앱 처리 흐름을 사용하고 GitHub 명령만 합성 응답으로 바꿉니다. 실제 사용자 저장소에 변경 요청이나 병합을 만들지 않습니다. 운영체제별 화면 검사의 실행 결과와 공개 배포 여부는 해당 버전의 최종 검증 기록에서 확인합니다.
