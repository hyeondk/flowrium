# 삭제와 휴지통

프로젝트와 대화는 마우스 오른쪽 클릭 또는 트랙패드의 보조 클릭으로 메뉴를 열 수 있습니다. 대화 관리 창에서도 삭제 확인 화면을 열 수 있습니다.

## 기본 삭제

- 대화는 Flowrium 휴지통으로 이동합니다. 메시지와 첨부 참조, 연결 정보를 보존합니다.
- 프로젝트는 Flowrium의 연결과 목록만 제거합니다. 작업 폴더와 프로젝트 안의 `.flowrium` 기록, 원래 앱의 프로젝트는 삭제하지 않습니다.
- 휴지통에서 같은 항목을 두 번 복원하거나, 이미 있는 대화와 프로젝트를 덮어쓸 수 없습니다.
- 실행 중이거나 대기 지시가 남은 대화는 정리한 뒤 삭제합니다. 복원한 대기 지시는 자동 실행하지 않습니다.
- 휴지통은 현재 ChatGPT 계정에 따라 구분합니다. 잠금과 계정 전환 후에는 이전 확인 요청을 사용할 수 없습니다.

## 원래 Codex 대화 처리

원래 Codex와 직접 연결한 대화는 확인 화면에서 아래 방법을 별도로 선택할 수 있습니다.

| 선택 | 원래 Codex | Flowrium 복원 |
| --- | --- | --- |
| Flowrium 항목만 이동 | 변경하지 않음 | 원래 연결과 표시 기록 복원 |
| 원래 대화도 보관 | 원래 목록에서 숨김 / 하위 작업 대화도 보관 시도 | 이번에 보관한 대화만 다시 보관 해제 |
| 원래 대화도 영구 삭제 | 원본과 자동 생성된 하위 작업 대화 영구 삭제 | Flowrium의 독립 사본만 복원 |

영구 삭제는 대상 이름을 정확히 입력하고, 원본과 하위 작업 대화에 대한 확인을 마쳐야 실행됩니다. 원래 계정과 기기를 대조하고 실제 하위 작업 목록을 다시 읽습니다. 확인 후 하위 목록이나 보관 상태가 바뀌면 새 확인이 필요합니다. 다른 Flowrium 항목이 같은 원본을 사용하거나 원래 대화가 실행 중이면 원본 처리를 차단합니다.

Codex의 하위 작업 대화는 원래 대화가 자동 생성한 대화입니다. 사용자가 별도로 만든 분기는 처리 목록에 없으면 대상이 아닙니다. 보관은 하위 작업 모두에 대해 성공이 보장되는 동작이 아니므로, 확인하지 못한 항목이 있으면 부분 처리로 표시합니다.

원본 처리에 실패해도 Flowrium 휴지통과 복원 자료는 유지합니다. 영구 삭제 요청의 결과가 확인되지 않는 경우에도 복원은 안전하게 독립 사본으로 수행하며, 원래 Codex의 상태는 직접 확인하도록 안내합니다.

## 지원 범위

번들 Codex 0.167.2에서 생성한 실제 프로토콜 스키마와 [공식 앱 서버 문서](https://learn.chatgpt.com/docs/app-server)의 `thread/archive`, `thread/unarchive`, `thread/delete`를 확인했습니다. `thread/delete`는 자동 생성된 하위 작업 대화도 삭제합니다. 실제 사용자 원본을 대상으로 삭제 검사를 실행하지 않으며, 삭제와 보관 회귀 검사는 합성 Codex 응답을 사용합니다.

ChatGPT 웹 대화는 Codex 대화와 별개입니다. ChatGPT 웹 기록을 삭제하는 공개 인터페이스를 이 기능에 연결하지 않았습니다. 웹 기록은 [ChatGPT의 공식 삭제 및 보관 안내](https://help.openai.com/en/articles/8809935-deleting-and-archiving-chats-in-chatgpt)에 따라 원래 서비스에서 직접 관리합니다.

## 검증

`tests/trash.test.cjs`는 실제 Flowrium 저장소와 합성 Codex 응답으로 로컬 복원, 프로젝트 원본 보존, 원본 보관과 영구 삭제, 하위 작업 영향 변경, 계정과 잠금, 실행 중 차단을 검사합니다. `tests/trash-ui-e2e.cjs`는 격리한 앱 프로필에서 우클릭과 키보드, 옆 대화와 초안 보존, 휴지통 및 재시작 복원, 영구 삭제 확인 화면을 검사합니다. 원본 처리 UI는 합성 IPC만 사용합니다. 두 앱의 정상 종료와 종료 작업 전체 완료도 함께 확인합니다.
