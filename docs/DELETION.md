# 삭제와 휴지통

프로젝트와 대화는 마우스 오른쪽 클릭 또는 트랙패드의 보조 클릭으로 메뉴를 열 수 있습니다. 대화 관리 창에서도 삭제 확인 화면을 열 수 있습니다.

## 기본 삭제

- 같은 계정과 기기의 Codex에 연결한 대화는 **원래 Codex 대화도 보관**이 기본입니다. 휴지통으로 이동하면 두 앱의 일반 목록에서 빠지고, 어느 앱에서든 보관을 해제하면 원래 대화가 돌아옵니다. **Flowrium 항목만 휴지통으로 이동**을 선택하면 상대 앱의 대화는 유지됩니다.
- 두 앱에서 같은 폴더 하나로 등록한 프로젝트는 **Codex 프로젝트 목록에서도 제거**가 기본입니다. 이 선택은 프로젝트 등록을 해제하고 작업 폴더와 파일, 대화 본문을 보존합니다. Flowrium 휴지통에서 복원하면 Codex 프로젝트를 다시 등록하고, 이전에 확인한 대화 중 다른 프로젝트에 배정되지 않은 대화를 다시 연결합니다. 여러 루트를 공유하거나 대응이 모호한 프로젝트는 원래 앱에서 범위를 확인하세요.
- 휴지통에서 같은 항목을 두 번 복원하거나, 이미 있는 대화와 프로젝트를 덮어쓸 수 없습니다.
- 실행 중이거나 대기 지시가 남은 대화는 정리한 뒤 삭제합니다. 복원한 대기 지시는 자동 실행하지 않습니다.
- 휴지통은 현재 ChatGPT 계정에 따라 구분합니다. 잠금과 계정 전환 후에는 이전 확인 요청을 사용할 수 없습니다.

## 자동 반영 시점

연결된 계정에서 Flowrium이 실행 중이면 백그라운드에서 Codex의 일반과 보관 목록을 확인합니다. 누락된 페이지, 연결 오류, 잘못된 계정 또는 기기만으로 삭제를 판정하지 않습니다. 실행 또는 대기 중인 작업은 정리가 가능해진 뒤 반영합니다.

- Codex에서 프로젝트 등록을 해제하면 Flowrium은 이전에 확인한 같은 등록 식별자와 폴더를 다시 대조한 뒤 프로젝트 카드를 휴지통으로 옮깁니다.
- 오프라인에서 이미 연결한 대화를 휴지통으로 옮기면 **재연결 시 Codex 대화도 보관**을 선택할 수 있습니다. 계정 연결이 돌아오면 원본과 하위 대화의 영향을 재검사합니다. 새 하위 대화가 발견되면 원래 앱에서 범위를 확인하세요.
- Flowrium이 로컬에서만 숨긴 항목과 휴지통에서 영구 정리한 항목은 자동 가져오기가 되살리지 않도록 계정과 기기에 연결된 식별자를 보관합니다.

## 이미 삭제한 항목이 보일 때

- Flowrium 목록에서 삭제를 눌렀을 때 같은 계정의 휴지통에 이미 옮긴 기록이 있으면 **목록 갱신**을 누르세요. 기존 휴지통 항목 한 건이 그대로 유지됩니다.
- 원래 Codex가 대화를 찾을 수 없다고 응답하면 Flowrium은 해당 계정의 일반 목록과 보관 목록에서 같은 식별자를 확인합니다. 두 목록에 모두 없으면 확인 창에 표시하며, 두 목록에서 사라졌고 직접 조회에서도 원본 없음이 확인되면 Flowrium의 연결 대화를 자동으로 휴지통에 옮깁니다. 복원하면 대화 내용이 독립 사본으로 돌아옵니다. 계정 불일치나 통신 실패는 삭제 완료로 기록하지 않습니다.
- Codex 데스크톱 자체의 사이드바 항목과 일반 ChatGPT 웹 프로젝트는 각 앱에서 관리합니다. Flowrium의 **목록 갱신**은 Flowrium에 보이는 항목을 갱신합니다.

### 공식 데스크톱에서 이 컴퓨터로 열 수 없다고 표시할 때

사이드바에 제목이 남아 있고 본문을 열 수 없다는 안내가 나오면, 공식 앱이 현재 컴퓨터에서 그 대화 기록을 찾지 못한 상태입니다. 이 문구만으로 원본의 삭제 여부를 판정할 수 없습니다.

1. 본문을 확인하려면 **다시 시도**를 누릅니다. 다른 기기에서 작업한 대화라면 해당 기기에서도 열어 보고 보관한 채팅 목록을 확인합니다.
2. 실제로 대화를 영구 삭제하려면 공식 데스크톱에서 정확한 제목의 행을 우클릭합니다. **영구 삭제**가 제공되면 확인 창에서 대상과 범위를 확인합니다.
3. 공식 목록에 제목만 남고 재시도와 삭제가 계속 실패하면, 제목과 오류가 보이는 부분만 잘라 공식 지원에 전달할 수 있습니다. [공식 지원 안내](https://help.openai.com/en/articles/6614161-how-can-i-contact-support)

## 휴지통에서 영구 삭제하기

휴지통의 항목을 선택한 뒤 **선택 항목 영구 삭제**를 누르거나 각 항목의 **영구 삭제**를 사용합니다. **휴지통 비우기**는 현재 계정의 전체 휴지통 기록과 과거 복원 완료 기록을 함께 확인합니다. 목록이 비어 있어도 이전 복원 완료 사본이 남았다면 비우기에서 정리할 수 있습니다.

확인 화면에서 대상 / 지울 복원 기록 수 / 함께 정리할 과거 복원 완료 사본 / 보존할 첨부와 보관 원문 참조를 확인합니다. 복원 불가 동의와 지정 문구를 정확히 입력해야 실제 삭제됩니다. 선택 삭제에서는 선택한 항목의 과거 복원 완료 사본도 함께 표시하며, 선택하지 않은 다른 휴지통 항목은 보존합니다.

이 작업은 **이 기기의 현재 계정에 속한 휴지통 JSON과 그 안의 복원 사본을 실제로 제거**합니다. 처리한 항목은 이 휴지통에서 복원할 수 없습니다. 프로젝트 작업 폴더 안의 첨부 원본 / 보관 원문 / 개정 기록과 다른 항목의 사본은 보존합니다. 함께 보관된 대화가 확인되면 **보관된 Codex 원본도 영구 삭제**에서 원본과 하위 대화의 목록을 볼 수 있습니다. 선택한 항목의 영구 삭제에서는 이 옵션이 기본으로 켜지고, 전체 휴지통 비우기에서는 꺼집니다. 실행 직전 대상과 계정을 다시 대조합니다.

확인 후 휴지통 내용이나 현재 참조가 바뀌면 새 확인이 필요합니다. 실행 / 대기 지시 / 계정과 잠금 상태도 다시 검사합니다. 여러 기록 중 일부를 삭제하지 못하면 실제 성공한 기록 수와 남겨 둔 기록을 구분해 표시합니다. 이미 삭제한 기록은 되돌리지 않으며 남은 항목은 다시 확인해 처리할 수 있습니다. 다른 기기 / 별도 백업 / 원래 서비스의 자료는 각각 관리합니다.

휴지통 확인 자료는 현재 계정 기록 2,000개 / 합계 512MB까지 검사하며 한 항목은 128MB를 넘을 수 없습니다. 확인 범위를 넘거나 저장 위치가 링크로 바뀐 경우에는 해당 자료를 삭제하지 않고 안내합니다. 참조 수는 휴지통 대화 사본에 기록된 항목을 기준으로 하며 프로젝트 연결의 전체 파일 수를 집계하지 않습니다. 프로젝트 폴더의 자료는 집계 여부와 관계없이 보존합니다.

## 원래 Codex 대화 처리

원래 Codex와 직접 연결한 대화는 확인 화면에서 아래 방법을 별도로 선택할 수 있습니다.

| 선택 | 원래 Codex | Flowrium 복원 |
| --- | --- | --- |
| Flowrium 항목만 이동 | 변경하지 않음 | 원래 연결과 표시 기록 복원 |
| 원래 대화도 보관 | 원래 목록에서 숨김 / 하위 작업 대화도 보관 시도 | 이번에 보관한 대화만 다시 보관 해제 |
| 원래 대화도 영구 삭제 | 원본과 자동 생성된 하위 작업 대화 영구 삭제 | Flowrium의 독립 사본만 복원 |

영구 삭제는 대상 이름을 정확히 입력하고, 원본과 하위 작업 대화에 대한 확인을 마쳐야 실행됩니다. 원래 계정과 기기를 대조하고 실제 하위 작업 목록을 다시 읽습니다. 확인 후 하위 목록이나 보관 상태가 바뀌면 새 확인이 필요합니다. 다른 Flowrium 항목이 같은 원본을 사용하거나 원래 대화가 실행 중이면 원본 처리를 차단합니다.

Codex의 하위 작업 대화는 원래 대화가 자동 생성한 대화입니다. 사용자가 별도로 만든 분기는 처리 목록에 없으면 대상이 아닙니다. 보관은 하위 작업 모두에 대해 성공이 보장되는 동작이 아니므로, 확인하지 못한 항목이 있으면 부분 처리로 표시합니다.

원본 처리에 실패해도 Flowrium 휴지통과 복원 자료는 유지합니다. 영구 삭제 요청의 결과가 확인되지 않는 경우에도 복원은 안전하게 독립 사본으로 수행하며, 원래 Codex의 상태는 직접 확인하도록 안내합니다.

## 지원 범위

번들 Codex 0.167.2에서 생성한 실제 프로토콜 스키마와 [공식 앱 서버 문서](https://learn.chatgpt.com/docs/app-server)의 `thread/archive`, `thread/unarchive`, `thread/delete`를 확인했습니다. `thread/delete`는 자동 생성된 하위 작업 대화도 삭제합니다. 실제 내장 Codex 서버와 격리된 임시 프로필로 두 방향을 검사합니다. 테스트 모델은 로컬 서버에서 합성 답변만 반환합니다.

ChatGPT 웹 대화는 Codex 대화와 별개입니다. ChatGPT 웹 기록을 삭제하는 공개 인터페이스를 이 기능에 연결하지 않았습니다. 웹 기록은 [ChatGPT의 공식 삭제 및 보관 안내](https://help.openai.com/en/articles/8809935-deleting-and-archiving-chats-in-chatgpt)에 따라 원래 서비스에서 직접 관리합니다.

## 검증

`tests/trash.test.cjs`는 실제 Flowrium 저장소와 합성 Codex 응답으로 로컬 복원, 프로젝트 원본 보존, 원본 보관과 영구 삭제, 하위 작업 영향 변경, 계정과 잠금, 실행 중 차단을 검사합니다. `tests/trash-ui-e2e.cjs`는 격리한 앱 프로필에서 우클릭과 키보드, 옆 대화와 초안 보존, 휴지통 및 재시작 복원, 영구 삭제 확인 화면을 검사합니다. 원본 처리 UI는 합성 IPC만 사용합니다. 두 앱의 정상 종료와 종료 작업 전체 완료도 함께 확인합니다.

휴지통 영구 삭제 단위 검사는 실제 합성 사본 파일 제거 / 공유 첨부와 원문 보존 / 과거 복원 사본 / 현재 사본 재사용 / 계정과 실행 상태 / 링크 / 일부 권한 실패와 재시도를 검사합니다. `tests/trash-purge-e2e.cjs`는 합성 자료만 사용해 선택 삭제와 비우기 / 취소와 확인 문구 / 원본과 현재 초안 보존 / 부분 실패 / 좁은 화면과 한글 어절 줄바꿈을 검사합니다. 실제 사용자 자료를 삭제하는 검사는 실행하지 않습니다.

`tests/trash-sync-native-e2e.cjs`는 임시 Codex 프로젝트와 대화에서 보관과 보관 해제, 양쪽의 영구 삭제, 휴지통 비우기 후 자동 가져오기 제외, 프로젝트 등록 해제 및 재등록 뒤 원본 파일과 대화 소속 보존을 검사합니다.
